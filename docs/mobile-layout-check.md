# 移动端 MD3 Expressive 与布局验证（Issue #1）

本机只运行前端调试、类型检查和测试；构建及安装包由 GitHub Actions 完成。

## 自动布局检查

在已具备 Playwright 的环境中，从仓库根目录执行：

```powershell
node tests/mobile-layout.mjs
```

脚本默认使用已安装的 Edge。若 Playwright 位于其他目录，可通过 `PLAYWRIGHT_MODULE` 指定模块路径；`PLAYWRIGHT_BROWSER` 可指定已安装的浏览器通道。脚本不会安装依赖或下载浏览器，也不要求启动 Vite。

检查使用项目实际全局 CSS 和 Svelte 编译后的组件 CSS，配合最小 DOM 样例验证布局。覆盖 320×480、320×568、375×667、390×844、430×932、720×1024 和 900×1440 的移动布局，以及 PC 的卡片列数、封面尺寸和歌曲列数。

断言检查快捷卡片文字空间、64px 导航与 56px 播放器及 8px 间距、48px 操作区域、整组导航选中背景、搜索歌曲列数、歌单表格的文字列宽与紧凑行高、滚动定位避让、导航隐藏后的播放条位置、矮屏播放器、歌词模式、登录弹窗及键盘展开。安全区使用顶部 44px、底部 34px 的模拟值。另检查明暗主题下的队列、确认弹窗、排序面板和播放器设置面板。

色彩检查使用现有 7 种强调色，包括模拟封面提色，在明暗两种主题下验证播放按钮、导航、抽屉、个人信息、快捷卡片和队列文字至少达到 4.5:1 对比度。此检查不替代实际设备验收，也不验证 API、登录或音频播放链路。

## 实际页面与设备验收

运行 `pnpm dev`，在浏览器中打开带 `?mobile` 的页面。该参数仅强制竖屏移动布局，横屏仍采用项目原有的 PC 布局。

- 首页：登录和未登录状态；320–430px 下快捷卡片文字可读。
- 导航：抽屉打开、关闭、切换页面；刘海与底部手势区域不遮挡操作。
- 播放条：长歌名、长歌手名；播放、暂停、队列按钮可操作，末尾歌曲不被遮挡。
- 歌曲列表：搜索、歌单、喜欢的音乐；文字截断正常，更多操作可用。
- 播放器：320×480 矮屏、封面与歌词模式、拖动进度、上下首与队列。
- 登录：弹窗可以滚动，软键盘展开后输入框与提交按钮可达。
- 旋转：横屏切换 PC 外壳，转回竖屏恢复移动布局。
- 主题：明暗模式、各预设主题色及跟随封面；自定义壁纸下正文和浮层仍清晰。
- 动效：按压、导航切换、播放器展开收起；减少动态效果设置下不出现弹性动画。

提交前运行 `pnpm check`、`pnpm test`。真实账号登录、音乐播放、iOS/Android 软键盘及安全区需要实机确认。
