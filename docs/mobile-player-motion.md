# 移动播放器 Motion 交互

本次覆盖 Motion 基础设施与移动端迷你播放器 ↔ 全屏播放器，合为一个草稿 PR。保留播放器布局、共享封面、渐变背景、横向切歌和弹层业务；封面/歌词的完整 `modeProgress`、桌面弹簧迁移及其他页面推广留待后续。

## 任务与行为

- [x] 精确锁定 `motion@14.6.0`，不升级已有依赖。
- [x] `createPlayerSurfaceController()` 管理 `closed / dragging / animating / open`、目标及唯一 `sheetProgress`。
- [x] 拖动直接更新进度，释放后用 Motion Spring 吸附；重复关闭不重启动画，反向与新手势不重置位置，过期回调不能卸载新一轮转场。
- [x] 点击、迷你条上滑、封面/手柄下拉、Escape、Android 返回汇入同一关闭入口；归零完成后才卸载。
- [x] 共享封面独立渲染，统一缩放；正文保持固定布局，通过裁剪、位移、透明度进入，底栏随同一进度退出。
- [x] 主转场暂停封面/歌词局部动画，全屏端点交还；同一事件中的待提交布局在下一次绘制前重测。
- [x] 取消、捕获丢失、窗口失焦及拖动中尺寸变化回到原目标；恢复可见后续跑，减少动态效果时直接完成目标状态。
- [x] 保留弹层返回优先级、原生歌词滚动、滑块、焦点隔离与恢复；卸载清理动画、订阅、样式及共享层。

手势复用现有 `morph-geometry.ts`：8px 锁轴阈值、1.2 方向比例、110ms 速度采样窗口，行程为视口高度的 45% 并限制在 300–440px。速度以向上为正。初始弹簧参数为 stiffness 420、damping 38、mass 1，仍需真机校准。

## 可运行检查

本地仅运行检查和测试，不执行构建、原生编译或打包：

```powershell
pnpm check:versions
pnpm check
pnpm test
```

`controller.test.ts` 覆盖实际 Motion 弹簧及可控的中断场景；`gesture.test.mjs` 覆盖指针序列；原 sheet 测试已改为实际渲染器的几何、状态和样式恢复断言，不再匹配旧 WAAPI 时间轴字符串。

浏览器回归复用现有数据 fixture 和项目已有的 Playwright 模块入口。启动仅监听本机的 Vite 开发服务，然后在另一终端运行：

```powershell
pnpm dev --host 127.0.0.1 --port 5184 --strictPort
# PR9_PLAYWRIGHT_MODULE 指向已有 playwright/index.mjs，不自动安装浏览器或依赖。
# 本机可设置 ZT_BROWSER_CHANNEL=msedge；默认使用 Playwright 已有 Chromium。
node scripts/browser/player-surface.mjs
```

结果及截图保存在 `browser-artifacts/`，不纳入提交。覆盖 320×480、375×667、430×932，明暗主题、反向/取消、快速模式切换、顶层队列返回、焦点恢复、歌词滚动、滑块、缺失/损坏封面、减少动画和尺寸变化。

Windows EXE 实测发现共享封面独立层缺少可见透明度、移动布局收起手柄被桌面标题栏遮挡。修复后新增实际 `opacity` / 图片加载断言，以及带 38px 标题栏的 375×667、400×720、400×700、400×701、420×800 回归，检查手柄命中、封面边界和主转场坐标连续性。

共享封面的可见性由主渲染器负责；桌面窄屏仅在内容与手柄中预留标题栏高度，全屏根层仍使用视口坐标。封面可用高度包含标题、控制区、间距和上下内边距，避免中等高度时溢出。新版原生 EXE 与 Android 真机验收需分别记录，不能用这些浏览器断言代替。
