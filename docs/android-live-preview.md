# Android 真机实时预览

修改 Android 的前端界面、动画或触摸交互时，如果手机和可调试的测试 APK 可用，优先在真机上预览并收集反馈。预览用于快速比较外观和交互，完成后仍要将确认的改动写入源码，并根据风险运行检查和验收。

## 连接设备和 WebView

1. 用 `adb devices -l` 确认设备在线；出现多个设备或同一手机的多个连接时，后续命令显式使用选定的 `-s <serial>` 或 `-t <transport-id>`。不要把历史设备地址、进程号或端口当成固定值。
2. 确认目标包名、版本、前台页面和预览范围，避免误操作其他应用。不同包名的数据、登录态和存储互相独立。
3. 通过 `adb -t <transport-id> shell pidof <package>` 获取当前进程号，再用 `adb -t <transport-id> shell cat /proc/net/unix` 查找对应的 `webview_devtools_remote_<pid>`。进程重启后重新查找；没有调试 socket 时，不要假定可以注入。
4. 用 `adb -t <transport-id> forward tcp:<local-port> localabstract:webview_devtools_remote_<pid>` 建立仅用于本次调试的转发，再通过 `http://127.0.0.1:<local-port>/json` 识别正确页面。使用 DevTools 或 Chrome DevTools Protocol（CDP）检查元素和应用临时更改，不要公开调试端口或记录账号、Cookie 和令牌。

## 预览和验证

- 对样式改动，使用 DevTools 样式面板、CDP 的 inspector stylesheet，或给特定元素设置临时行内样式；WebView 的 CSP 可能阻止直接插入 `<style>`。对动画参数，可以在当前页面临时拦截目标元素的 Web Animations 调用做 A/B 比较。只修改测试所需的节点和属性，并记录原值及恢复方法。
- 显示给用户实际操作，收集速度、阻尼、圆角和触摸反馈等主观感受；分别检查竖屏、横屏、快速反向、系统返回及减少动态效果等受改动影响的场景。确认预览确实生效后，再据反馈修改源码。
- 使用截图、元素边界和帧间隔帮助定位；`requestAnimationFrame` 帧间隔只是辅助指标，不等同于实际显示帧率或 GPU 呈现耗时。性能比较要说明设备状态、样本数量和偶发掉帧，不能仅凭一次采样声称完全解决。
- 预览结束时恢复临时样式、脚本补丁和模拟参数，移除本次 `adb forward`；若用户仍在体验临时预览，保留至体验结束并说明其有效期。不要更改系统设置、权限、用户数据或应用签名来制造预览条件。
- 临时注入只作用于当前 WebView，不会更新源码或已安装 APK；刷新页面、进程重启或连接中断后可能失效。原生 Kotlin/Rust、依赖、启动配置或需要完整资源加载的变更，不能仅靠注入视为验证。
- 不在本地构建或打包。需要新的 APK 时使用远程 CI；安装前确认包名和签名。签名不一致时不得卸载旧包来强行覆盖；可按任务授权使用独立包名的预览版，并说明数据不共享。

汇报时区分临时预览、源码修改、自动检查和新 APK 真机验收，说明未覆盖的场景。手机不可用或不可调试时，先完成可做的检查，并明确指出真机验证尚未完成。
