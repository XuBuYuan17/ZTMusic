# 移动端导航与动画

## 实际结构与修改计划

项目使用 Svelte 5，导航由 `router.svelte.ts` 的视图状态与返回栈实现。保留该结构，不引入 Vue Router、动画库或新的依赖。

原实现保留主页面，但卸载详情页；详情出场克隆整个 DOM，进入和返回都沿 Y 轴移动。播放器展开使用 Mini 容器，收起却寻找内部图片，目标尺寸和位置可能不一致。

本轮按以下顺序完成：

1. 区分 Tab、Push、Pop，统一时长与位移，并处理动画中途取消。
2. 用有上限的详情页缓存替代离场 DOM 克隆，保留筛选、排序与滚动状态。
3. 对齐 Mini 与全屏播放器的封面坐标，统一正向、反向和拖拽后的动画。
4. 用独立自检和浏览器回归验证导航、缓存、播放器及桌面布局。

## 本轮行为

| 场景 | 动画 |
| --- | --- |
| Tab / 搜索切换 | 170ms，淡入，Y 轴 8px |
| Push | 260ms，新页从 X +32px 进入，旧页向 X -12px 离开 |
| Pop | 260ms，前页从 X -12px 返回，当前页向 X +32px 离开 |
| Mini → 全屏及反向 | 300ms，封面 FLIP 与页面淡入 / 淡出、Y 轴 40px 同步 |
| 减少动态效果 | 直接完成导航与播放器打开 / 关闭 |

主页面与搜索首次访问后保留；详情按最近访问保留最多 6 页。超过上限的页重建，使用原有数据缓存。页面缓存和路由返回栈分别处理，不改写业务导航结果。

离场页使用原 DOM，设为 inert，退出动画结束后隐藏。所有详情加载更多回调先检查是否为当前页面，避免隐藏歌单操作另一页。滚动恢复观察当前页的实际尺寸，不再观察隐藏首页。

动画使用 transform / translate 和 opacity。共享封面飞入时详情页不额外横移，避免封面落点受父层位移影响。此次不改 API、Rust、播放状态机、原生媒体会话或桌面页面切换。

已有底部面板继续使用 240–280ms 的垂直滑动；歌词切换和高亮沿用原有逻辑，不增加歌词逐行入场。Android 返回键继续复用已有弹层优先关闭和 router.goBack 链路。

## 验证

- `pnpm verify`：版本、Svelte / TypeScript 检查、66 个测试文件、前端构建通过。
- `node tests/mobile-navigation.mjs`：首页 → 歌单 → 歌手 → 返回，筛选、原 DOM、深层滚动位置与数据缓存保留；搜索跨 Tab 保留；快速导航只留一个可交互页面；缓存上限；封面正反向落点通过。
- `node tests/mobile-preview.mjs`：浅色 / 深色页面、320–720px、弹层焦点、拖拽、减少动态效果及 PC 回归通过。
- `node tests/mobile-layout.mjs`：320–900px 布局、安全区域、键盘、歌词、弹层与桌面布局通过。

浏览器测试需要已有 Playwright 和浏览器，不自动下载。可用 `PLAYWRIGHT_MODULE` 指定现成模块；两个页面测试可用 `MOBILE_PREVIEW_URL` 指向当前开发服务器。

未完成真机验收：新 APK 的系统返回键、锁屏 / 后台、低端机与高刷新率帧率。浏览器模拟不能证明这些行为；现有 APK 不包含本轮代码时也不能作为验收依据。
