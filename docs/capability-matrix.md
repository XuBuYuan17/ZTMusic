## 1. 图例

### 能力标记

| 标记 | 含义 |
| --- | --- |
| **共同** | 两端都能执行，差别只在呈现 |
| **仅 PC** | 只有 PC 外壳能触达 |
| **仅移动** | 只有移动外壳能触达 |
| **平台** | 由运行平台能力决定，非布局决定 |
| **两端都无** | 共同缺失，记录但不计入两端差异 |

### 处理方向（每条差异必须落到一类）

| 方向 | 判据 | 典型场景 |
| --- | --- | --- |
| **补入口** | 能力函数已存在，缺的只是可发现的触发点 | 分享 / 加入队列的函数两端共用 |
| **统一实现** | 两份代码做同一件事，或判定源用错了维度 | 设置页两套、右键被布局判定拦掉 |
| **布局适配** | 能力相同，呈现不同，改列数/密度/位置即可 | 表格↔卡片、下拉↔弹层 |
| **保留平台限制** | 该能力确实只在某平台存在 | Android 返回、原生媒体控制 |

**不设「不处理」**：每条差异要么归到这四类，要么明确标为「两端都无」而不算差异。

## 4. 其余页面

紧凑写法：每页列「展示模块」「可操作行为」「两端差异 → 处理方向」。

## 6. 平台限制清单（保留，不对齐）

| 能力 | 限制所在 | 影响 | 结论 |
| --- | --- | --- | --- |
| Android 返回键/返回手势 | 仅 Android 原生 WebView | 桌面无此输入 | 保留 |
| 原生媒体控制（SMTC / MPRIS） | 桌面原生 | 移动端走 Web Media Session | 保留（`native-media-platform.ts` 已有选择逻辑） |
| 系统集成设置项 | `engine.native` | 非原生引擎不显示 | 保留（判定正确） |
| WebDAV 跨域 | 浏览器同源策略 | Web 端连不上部分服务器 | 保留（属运行环境） |
| 本地文件系统直读 | 未使用；导入走 `<input type="file">` | 全平台可用 | 无需限制 |

**没有一项页面级能力属于「平台不支持」。** 本批发现的差异全部是入口缺失、实现分叉或布局选择。
