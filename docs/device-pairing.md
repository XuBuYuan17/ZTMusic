# 哲听设备扫码登录与迁移

已登录设备打开「设置 → 数据与账号 → 授权另一台哲听」。新设备打开登录页里的「哲听扫码登录」。旧设备扫二维码或粘贴配对码，核对六位验证码、勾选要迁移的项目，双方各自确认。

至少一台设备须已有网易云会话。授权后的会话仍由现有 API 验证，其有效期和撤销行为由网易云决定。两台设备须配置同一个 HTTPS 网易云 API 地址。

可选项包括本机在线歌曲历史（最多导出 200 条，保留目标设备已有记录）、在线歌曲统计（最多 500 条最近记录）、自定义歌单分组和常用设置。常用设置在下一次冷启动应用。云端收藏、歌单和云端最近播放会在登录后从网易云重新拉取。本地音频、壁纸、播放队列和 WebDAV 凭据留在原设备。

## 本地调试

Vite 开发服务自带同源配对中转。可用两个浏览器配置文件分别登录和接收，避免共享登录状态。相机扫码依赖运行环境支持 QR 格式。WebView 不支持、权限被拒或没有相机时，可复制并粘贴配对码。

## 自托管中转

在已有 Node 运行环境执行：

    node scripts/device-pairing-relay.mjs

服务默认监听 127.0.0.1:5714，可用 ZHETING_PAIRING_PORT 指定端口。在自己的 HTTPS 反向代理中转发 /device-pairing 及其子路径。构建网页或安装包时，将 VITE_DEVICE_PAIRING_URL 设为完整的 HTTPS 配对地址，例如 https://example.com/device-pairing。GitHub Actions 的 Windows 安装包和 Android APK 从同名仓库变量读取该地址。生产版本缺少该配置时会提示配对服务尚未配置。

配对中转只存短期密文，三分钟过期，一个配对码接受一次写入。接收方私钥保留在新设备上，配对码中的加密秘密不发给中转。Cookie 和迁移明文只在两端应用中处理。反向代理应关闭 Authorization 请求头和请求体日志。公网部署时可在现有反向代理中设置速率限制，避免匿名请求占满配对空间。

用合成凭据测试加密、授权边界、过期码和取消：

    node scripts/device-pairing.test.mjs
